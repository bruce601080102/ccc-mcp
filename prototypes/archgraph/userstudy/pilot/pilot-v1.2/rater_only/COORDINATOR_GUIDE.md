# 施測者操作指引（協調者與作者專用，不發給測試者）— pilot-v1.2

## 1. 這次預試能證明什麼、不能證明什麼

- **能證明**：題目與材料的流程能否走完；材料是否有缺漏、矛盾或找不到的地方；標準答案與題目是否有矛盾；計時、錯誤紀錄與回報流程是否可用。
- **不能證明**：新手能否理解；ccc-mcp 是否優於 B 或 C；任何統計差異。兩位測試者不足以比較條件。
- **不評估** `STUDY_PROTOCOL.md` 第 8 節的驗收判準。兩人的結果不得寫成 ACCEPT、REVISE 或 STOP。
- 測試者不是新手。預試結果不得寫成「新手驗證通過」，也不得寫成已完成正式研究。

## 2. 發放材料

- 版本為 **pilot-v1.2**（測試者套件與 v1.1 逐位元組相同；變動只在評分與彙整規則）。P1 只拿到 `pilot/pilot-v1.2/tester_P1/`；P2 只拿到 `pilot/pilot-v1.2/tester_P2/`。
- **絕對不要**給任何人 `pilot/pilot-v1.2/rater_only/`（含答案、評分規則、指派表）。
- 發放前，在 `userstudy/` 目錄執行 `python freeze.py check`，必須顯示 `FREEZE CHECK PASSED`。
- `pilot/pilot-v1/`（`pilot/tester_P1/`、`pilot/tester_P2/`、`pilot/rater_only/`）與 `pilot/pilot-v1.1/` 皆已被取代，**不得發放**。

## 3. 指派（同時記錄於 `pilot/pilot-v1.2/rater_only/assignment.json`）

| 測試者 | block1 notes | block2 bookmarks | block3 todos |
|---|---|---|---|
| P1 | A | B | C |
| P2 | C | B | A |

區塊順序對兩位測試者都是 notes → bookmarks → todos。

## 4. 條件 B 的來源（必須在報告中照寫）

條件 B 是 **Claude 根據完整事實表（`facts.json`）撰寫的固定文字基線**。它不是獨立 AI 摘要工具的輸出，也不是人類撰寫。它在預試與正式研究期間不得修改。

## 5. 學習效應與材料消耗（必須在報告中說明）

- 三個案例結構相同。固定的區塊順序讓**學習效應與案例順序無法分開**。兩人預試不足以估計它。
- **bookmarks 與 todos 在本次預試後就已曝光**。正式研究若要使用，須由未曝光的受試者作答，或另換案例。由你決定，不要自行假設它們仍可用於正式研究。

## 6. 施測流程

1. 確認 `freeze.py check` 通過，然後交給測試者。
2. 測試者自行依 `TESTER_GUIDE.md` 作答。施測者只回答程序性問題，**不解釋材料內容，也不提示答案**。若測試者問到材料內容，記錄在紀錄表中。
3. 收回三份作答表、`TIMING_AND_ERROR_LOG.csv`，以及有需要時的回報（依 `FEEDBACK_FORMAT.md`）。
4. 收回後不得修改這些檔案。若要修正，另存副本並記錄。
5. 檢查完成：`python completion.py <收回資料夾> <P1 或 P2>`，必須顯示 `COMPLETE`。

## 7. 完成的定義（T07）

一位測試者完成預試，當且僅當：三個區塊都有作答表，且各表的 `start_time`、`end_time` 為 HH:MM:SS，`questions_asked_for_help` 為大於等於 0 的整數，`notes` 存在（可空白）；並有 `TIMING_AND_ERROR_LOG.csv`（表頭未被改動，列數可為 0）。

**個別留白允許**：留白的題目得 0 分，計為未作答，不會使測試者未完成。`不確定` 同樣允許。

## 8. 評分

1. 評分者必須**不是作者**。作者可以協助核對，但不能單獨評分。
2. 清單題的名稱若與標準答案不完全相同，**評分前**統一成標準名稱，並把每個改寫記在 `normalization_log.md`（新增檔案）。
3. 對每位測試者的每份作答表執行 `python score.py rater_only/keys_<case>.json <作答表>`，保留輸出。
4. 逐條判定 `claim_code`（TRUE / FALSE / UNSUPPORTED）。預試只需一位非作者評分者。
5. 輸出 `invalid` 欄位的所有項目，逐一檢查，並在紀錄中說明如何處理。
6. 彙整：`python aggregate.py <收回根目錄> <輸出.csv>`。預設只計入完成的測試者；`--include-incomplete` 會把未完成者也計入，只用於檢查。

## 9. 指標定義（T07，門檻數值不變）

- **Q10 整題正確**：答案、阻擋原因、待執行動作三個子分數全部正確。
- **Q10 錯誤理解率** = 錯誤子分數數量 ÷ 全部應答子分數數量（每題 3 個子分數）。留白與無效答案計為錯誤。
- **Q10 棄答率** = `不確定` 的子分數數量 ÷ 全部應答子分數數量（3N）。`不確定` 得 0 分，但**不是明確錯誤主張，不計入錯誤**；棄答率獨立計算、獨立報告。
- **危險誤判**（在存在未解除阻擋條件的 Q10 作答中，答「能」）同時報告三種比例：
  - **全體比例**：危險誤判 ÷ 存在阻擋條件的 Q10 作答數（留白與 `不確定` 留在分母）。
  - **明確決策比例**：危險誤判 ÷ 存在阻擋條件且答「能」或「不能」的 Q10 作答數。
  - **棄答率**：答「不確定」 ÷ 存在阻擋條件的 Q10 作答數。
- **Q09 正確率** = 正確格數 ÷ 21。
- 所有比率都只描述這次兩人的結果，不做統計檢定。

## 10. 每個區塊要記錄的項目

- 逐題答案、分數、不確定回答、留白。
- 作答時間（由 `start_time` 與 `end_time` 計算）。
- 求助次數。
- 錯誤理解（`TIMING_AND_ERROR_LOG.csv` 中 `claim_code` 為 FALSE 的列）與操作疑惑（回報與紀錄中的 `unclear_wording`）。

## 11. 停止與變更

- 測試者中途無法完成，照實記錄，不補寫。
- pilot-v1.2 期間**不得修改材料或套件**。若要修改，建立新版本（pilot-v1.3），重新 `build_pilot.py`、`freeze.py write`，並註明舊版結果不再適用。
- 完成或中止後，停止；正式招募與正式研究需另行核准。
