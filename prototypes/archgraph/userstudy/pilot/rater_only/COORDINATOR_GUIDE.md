# 施測者操作指引（協調者與作者專用，不發給測試者）

## 1. 這次預試能證明什麼、不能證明什麼

- **能證明**：題目與材料的流程能否走完；材料是否有缺漏、矛盾或找不到的地方；標準答案與題目是否有矛盾；計時與錯誤紀錄流程是否可用。
- **不能證明**：新手能否理解；ccc-mcp 是否優於 B 或 C；任何統計差異。兩位測試者不足以比較條件。
- **不評估** `STUDY_PROTOCOL.md` 第 8 節的驗收判準。兩人的結果不得寫成 ACCEPT、REVISE 或 STOP。
- 測試者不是新手。預試結果不得寫成「新手驗證通過」或「已有人類受試者」以外的說法。

## 2. 發放材料

- P1 只拿到 `pilot/tester_P1/`；P2 只拿到 `pilot/tester_P2/`。
- **絕對不要**給任何人 `pilot/rater_only/`（含答案、評分規則、指派表）。
- 發放前，在 `userstudy/` 目錄執行 `python freeze.py check`。必須顯示 `FREEZE CHECK PASSED`。失敗時不得發放，先找出是哪個檔案被改動。

## 3. 指派（同時記錄於 `pilot/rater_only/assignment.json`）

| 測試者 | block1 notes | block2 bookmarks | block3 todos |
|---|---|---|---|
| P1 | A | B | C |
| P2 | C | B | A |

區塊順序對兩位測試者都是 notes → bookmarks → todos。

## 4. 學習效應與材料消耗（必須在報告中說明）

- 三個案例結構相同。固定的區塊順序讓**學習效應與案例順序無法分開**。兩人預試不足以估計它。
- **bookmarks 與 todos 在本次預試後就已曝光**。正式研究若要用它們，測試者必須是全新的；否則須另外替換案例。這一點由你決定，不要自行假設它們仍可用於正式研究。
- B 組仍是作者撰寫的基線（見 `B_text.md` 開頭），不是 AI 摘要，也不是人類撰寫。

## 5. 施測流程

1. 確認 `freeze.py check` 通過，然後交給測試者。
2. 測試者自行依 `TESTER_GUIDE.md` 作答。施測者只回答程序性問題（例如「怎麼開 HTML」），**不解釋材料內容，也不提示答案**。若測試者問到材料內容，記錄在紀錄表中。
3. 收回：三份作答表（`response_sheets/block*.json`）、`TIMING_AND_ERROR_LOG.csv`、回報（依 `FEEDBACK_FORMAT.md`）。
4. 收回後不得修改這些檔案。若要修正，另存副本並記錄。

## 6. 評分

1. 評分者必須**不是作者**。作者可以協助核對，但不能單獨評分。
2. 清單題的名稱若與標準答案不完全相同（例如同義詞、少字、多字），**評分前**統一成標準名稱，並把每個改寫記在 `pilot/rater_only/normalization_log.md`（新增檔案）。不可在沒有記錄的情況下改寫。
3. 執行 `python score.py rater_only/keys_<case>.json <作答表>`，記錄每份作答的輸出。
4. 逐條判定 `claim_code`（TRUE / FALSE / UNSUPPORTED）。預試只需一位評分者，不計算 kappa；若要用於正式研究，需兩位獨立評分者。
5. 輸出 `invalid` 欄位的所有項目，逐一檢查，並在紀錄中說明如何處理。

## 7. 每個區塊要記錄的項目

- 題目逐題答案、分數（含 `q09_accuracy` 與 `q10_all_correct`）、錯誤理解率、不確定率。
- 作答時間（由 `start_time` 與 `end_time` 計算）。
- 求助次數。
- 錯誤紀錄表與回報中，使用者對畫面的疑惑。

## 8. 停止與變更

- 測試者中途無法完成，照實記錄，不補寫。
- 預試期間**不得修改材料**。若要修改，產生新版本（例如 `pilot-v2`），重新 `build_pilot.py` 與 `freeze.py write`，並註明舊版的結果不再適用。
- 完成或中止後，停止；正式招募與正式研究需另行核准。
