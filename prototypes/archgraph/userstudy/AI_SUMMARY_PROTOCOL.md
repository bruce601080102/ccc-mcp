# 正式研究用 AI 摘要的產生方式（尚未執行）

本文件規定正式研究中條件 B 的 AI 摘要如何產生。**目前沒有執行任何模型呼叫。**
目前的條件 B 是 Claude 根據完整事實表撰寫的固定文字基線（見 `materials/*/B_text.md` 開頭的標示），不是獨立 AI 摘要工具的輸出，也不能冒稱為 AI 生成。

## 1. 產生方式

1. 每個案例各產生一份摘要，共三份。
2. 使用 `AI_SUMMARY_PROMPT_v1.md`，把 `materials/<case>/facts.json` 的內容放入 `{FACTS_JSON}`。
3. **獨立產生**：在全新的對話或工作階段中執行。不得提供標準答案（`keys.json`）、題目（`questions.md`）、條件 A 或 C 的材料，也不得提供其他案例的摘要。
4. 同一案例只產生一次。若要重新產生，必須使用新的紀錄列，並說明原因。
5. 產生後不得人工修改內容。若需修正，必須重新產生。

## 2. 必須記錄的內容

每次產生都記錄在 `AI_SUMMARY_RECORD.md` 的一列中：

| 欄位 | 內容 |
|---|---|
| 案例 | case1_notes / case2_bookmarks / case3_todos |
| 提示詞版本 | v1 |
| 提示詞 SHA-256 | 施測前記錄的值 |
| 輸入事實表 SHA-256 | `facts.json` 的雜湊值 |
| 模型名稱與版本 | 例如回傳的模型 ID |
| 溫度與其他參數 | 全部列出，若為預設值也要寫 |
| 產生日期時間 | |
| 工作階段 | 是否為全新工作階段（是／否） |
| 輸出內容 SHA-256 | 摘要檔的雜湊值 |
| 字數 | |
| 是否人工修改 | 應為「否」 |

## 3. 施測前凍結

- 三份摘要與提示詞都要在**第一位受試者開始前**完成，並記錄雜湊值。
- 施測前，任何人不得查看摘要的內容以外的評分資訊。

## 4. 與條件 B 的關係

- 固定文字基線（現行 `B_text.md`，Claude 根據完整事實表撰寫）保留為**內部預試基線**，不得用來代表 AI 摘要的表現。
- 正式研究應同時比較 AI 摘要與手寫基線；如果只有其中一種，報告必須說明原因。
