## 0. 先產生要操作的圖（只需一次）

在 ccc-mcp 專案外建立一個資料夾，產生 notes-cli 的 TASK-0001～0003 架構圖：

```bash
cd ~/Desktop/python_project/sideproject/ccc-mcp/prototypes/archgraph/userstudy
../../../.venv/bin/python build_cases.py ~/ccc-t08-review --facts
```

產生的檔案位於：

- `~/ccc-t08-review/case1_notes/TASK-0001/architecture.html`
- `~/ccc-t08-review/case1_notes/TASK-0002/architecture.html`
- `~/ccc-t08-review/case1_notes/TASK-0003/architecture.html`

用瀏覽器開啟。頁面上方是「新手」分頁，另一個分頁是「計畫（Planned）」。工程視圖的資料在同一資料夾的 `engineer.json`。

## 1. 四項操作檢查

每一項都請你自己看、自己判斷，並把結果填在第 2 節的表格中。

**項目 1：TASK-0001 的核准條件**
- 開啟 `case1_notes/TASK-0001/architecture.html`。
- 找出畫面上的核准條件（READY、NEEDS_COMMIT 或 BLOCKED），以及你看到的阻擋原因。
- 記錄：條件、阻擋原因（如果有），以及你是否看得懂它為什麼是這個條件。

**項目 2：TASK-0003 的三個狀態是否分開**
- 開啟 `case1_notes/TASK-0003/architecture.html`。
- 找出 Git 提交狀態、主機測試結果、核准條件，三者是否分開顯示。
- 記錄：你能否分辨這三者，以及它們各自的顯示內容。

**項目 3：TASK-0003 的待確認對應**
- 在同一頁找出「待確認的新舊對應」。
- 判斷你能否從兩端節點找到它（從 `notes/storage.py` 或 `notes/migrate.py` 其中一個節點出發）。
- 記錄：找到的路徑，或找不到的原因。

**項目 4：計畫與實際的區分**
- 開啟「計畫」分頁，並與「新手」分頁比較。
- 判斷你能否分辨計畫中的檔案與實際的變更。特別注意 TASK-0001 的 `notes/util.py`：它在計畫分頁以計畫依賴的端點出現，但在核准條件中被列為超出計畫（TASK-0001 因此為 BLOCKED）。
- 記錄：你的判斷，以及你覺得哪裡容易混淆。
