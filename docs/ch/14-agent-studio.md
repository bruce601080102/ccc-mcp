# 14. Agent Studio：建立你自己的角色

Agent Studio 讓你建立自己的角色、寫下它的指令，並把它放進工作流，與內建角色一起工作。它在本機 Web 控制台（`ccc-mcp ui`）使用，位置是專案側欄的**角色工作室**。ChatGPT、MCP 工具、CLI 與設定檔都碰不到它：角色的指令只能由坐在控制台前的人寫。

## 1. 它是什麼，不是什麼

自訂角色是**疊在某個內建角色之上的名字與一段指令**，那個內建角色稱為*基礎角色*（SA、SD、RD、SD/RD、CR/REVIEW、SR、AR、SEC、QA、SW，或日常角色之一）。凡是由程式碼強制的事，都由基礎角色決定：能不能寫檔、報告如何判定、用哪種沙箱、是否擔任審查者。**自訂角色不可能靠指令的文字取得任何權限。**

本版本是第一階段，**沒有 AI 評分 Prompt 的功能**。第 4 節的 Prompt 健檢是免費的本機文字檢查。用語言模型替角色 Prompt 評分屬於後續階段的規劃，目前不存在，控制台也沒有任何地方宣稱它存在。

## 2. 建立角色

1. 開啟**角色工作室**，選**新角色**。
2. 填**名稱**（最多 24 個字元，不可含 `< > & " ' \`` 或反斜線，且須以字母或數字開頭）、選填的簡短說明，並選頭像。
3. 選**基礎角色**。建立後不能更改；想以另一個基礎角色開始，請用**複製角色**。
4. 寫指令（第 3 節）。可選擇調整**能力**（僅供顯示：用來畫團隊圖，不會改變任何分數），並可在**進階**中為這個角色指定 provider、模型、思考等級與額度不足接手。
5. **建立角色**。它從第 1 版開始，且為啟用狀態。一個專案最多 30 個自訂角色。

角色不會被刪除：**停用**會保留所有版本與快照，已開始的任務仍用它當初的角色繼續跑。

## 3. 寫指令：引導式章節或完整文字

- **引導式章節**是六個短欄位：目標、職責、限制、輸入輸出格式、協作規則、失敗時怎麼辦（每欄最多 4,000 字元）。
- **完整文字**是一個自由欄位（最多 16,000 字元），原樣送出，不修剪、不改寫。

兩種內容都會一直保留，所以切換模式不會丟掉你寫的字；只有目前使用的模式會被送出。**預覽將送出的內容**會顯示完整訊息，並標出每一段由誰能修改（你、ccc-mcp 固定契約、provider 外層）。預覽不呼叫任何模型、不建立執行、不儲存任何東西。真正執行時，會把實際送出的文字存起來，其中疑似憑證的字串會先遮蔽。

## 4. 免費的 Prompt 靜態健檢

**檢查我的指令**用單純規則讀你的文字：不呼叫模型、不送出任何東西、不花 token。它會指出缺少的面向、互相矛盾之處，以及因為 ccc-mcp 在別處已固定而不可能生效的寫法。它**不給分數**。偵測以關鍵字為主，所以「沒有發現」不代表沒問題；標出一句「忽略規則」也不會讓它變安全：真正的保護由程式碼強制（第 7 節）。

## 5. 版本與快照

- 每次儲存都是一個**不可變的新版本**，附指紋（SHA-256）。**歷史**分頁列出版本，並顯示任意兩版的差異。儲存時必須帶上你開始編輯的版本，所以兩個人不會互相覆蓋。
- 任務開始一輪工作時，ccc-mcp 會**釘住**團隊名單：把每個自訂角色凍結成**快照**（定義、基礎角色、解析後的 provider 設定、固定契約清單），並以該內容的雜湊作為身分。之後編輯或停用角色，都影響不到這個任務。計畫核准會綁定被釘住的名單，所以為某個團隊給的核准，不能拿去讓另一個團隊繼續。
- 任務的每一步都有自己的步驟身分，所以同一個角色用兩次仍是兩個步驟；結果、評分與聊天室都會標示是哪個角色、哪一版發言。

## 6. 把角色加入工作流

在專案的**設定 → 工作流**中組合你自己的工作流，任何基礎角色相符的步驟都可以選用自訂角色。工作流需要 1 到 12 個步驟，且必須以產出型角色（SA、SD、RD 或 SD/RD）開頭；一個專案最多 20 個自己的工作流。已停用的角色不能加入工作流，仍使用它的工作流也無法啟動新任務。審查型角色可以把工作退回給做出該工作的步驟，輪數上限與內建工作流相同。

## 7. 固定契約與安全限制

作用在角色上的規則有三種，其中只有一種是文字：

| 種類 | 誰寫 | 你的指令能改嗎 |
| --- | --- | --- |
| 你的指令 | 你，在角色工作室 | 能 |
| 固定執行契約（操作者政策、報告格式、交接與 Gate 規則） | ccc-mcp，有版本與雜湊 | 不能 |
| 程式碼強制的規則（唯讀或可寫、沙箱、計畫核准、專案授權、主機執行的測試、Gate 判定、額度接手） | ccc-mcp 程式碼 | 不能 |

這些全都在**同一則訊息**裡送給 provider。標記讓結構更清楚，但模型可以不理會：這不是訊息層級的權限隔離。安全建立在第三列。

如果任務被釘住期間 ccc-mcp 自己的固定契約改變了，變動會被分類。意思相同的措辭調整會被記錄，任務照常繼續；意思改變則會在下一步之前停住任務，直到你在任務頁檢視變動，並輸入寫有該任務、步驟與契約的確認文字。專案的寫入授權不會替你接受它。

## 8. 匯出、匯入與信任確認

**匯出備份**（專案總覽）與 `ccc-mcp project export` 現在會包含自訂角色：定義與每個版本、凍結的快照與其雜湊、名單釘選與核准綁定、角色歷史，以及你的工作流所引用的角色。不包含每次執行完整的 provider 文字（內含專案 Context）、獨立儲存的 runtime API key，以及可執行的 MCP server 註冊。若角色看起來含有憑證，匯出會直接拒絕。

備份仍包含 Context、Agent 報告、執行指令、任務紀錄、角色 Prompt，以及保留的專案與 provider 設定。這些欄位可能包含私人內容或未被偵測到的憑證；匯出沒有對所有欄位統一遮蔽。部分內容在寫入時會拒絕或遮蔽符合規則的憑證，但規則不能保證涵蓋所有機密。請將備份視為敏感檔案，分享前檢查內容。

**匯入備份**（所有專案）與 `ccc-mcp project import` 把檔案當作不可信的資料。在寫入任何東西之前，每個定義、雜湊、快照、名單與引用都會重新檢查；只要有一項不過，整份備份就會被拒絕，且不留下任何東西（匯入是一次資料庫交易）。檔案裡的校驗碼只證明它沒有損壞，不證明是誰寫的。

無論檔案怎麼宣稱：

- 每個匯入的角色都以**等待確認**的狀態到達，每份匯入的快照都是未信任。檔案來源裝置的信任紀錄只當作歷史供你閱讀，不計入。
- 未確認的角色不能被編輯、啟用、加入新任務或執行，不論從哪條路：資料庫會拒絕引用未信任快照的執行。
- 開啟專案的寫入權限不會確認任何東西。ChatGPT、MCP 工具、worker 與 CLI 都不能確認角色。

要確認角色，請在**角色工作室**打開它。**檢視**分頁會顯示檔案的來源（它的專案、匯出時間與指紋，這些只是對方的說法）、角色能做什麼（由基礎角色決定，不是檔案）、完整指令、各個版本、檔案裡的快照，以及使用它的工作流。**確認並啟用…**會要求你輸入一段包含角色 id、版本與指紋前幾碼的文字，避免誤確認另一個角色或被改過的版本。確認會記錄由控制台操作，啟用這一個角色，並確認該版本的快照（較舊的快照只有在你勾選，或之後在**歷史**中逐一確認時才會確認）。快照本身永遠不會被修改。

重複匯入同一個檔案，或匯入到已有 ccc-mcp 紀錄的資料夾，都會被拒絕。專案之間的角色彼此獨立，即使角色 id 看起來相同。資料夾裡自己的原始碼與未提交的修改都不會被碰；匯入的專案維持唯讀，未完成的任務會是暫停狀態。

**相容性。** 沒有角色紀錄的備份仍寫成版本 1，舊版可以讀：從未使用自訂角色的專案，即使跑過任務，匯出的內容也和以前完全相同，因為只有用到自訂角色的任務才會釘住名單。含角色紀錄的備份是**版本 2**：早於 Agent Studio 的版本會以「Unsupported project bundle version」拒絕它，而不是只匯入一半專案。本版本兩種都能讀。沒有降級的路：想在舊版使用版本 2 的專案，只能在舊版重新建立。

## 9. 已知限制

- Prompt 健檢、預覽與匯入檢查的訊息由後端以英文產生；控制台的標籤已翻譯。
- 匯入後暫停、且釘在較舊快照上的任務，要等你確認那一份快照才能繼續：在**檢視**分頁勾選，或之後在該角色的**歷史**分頁使用**確認這份快照…**。
- 真實 provider 執行（Codex、Claude Code）在測試中以模擬的 CLI 涵蓋；使用已安裝並登入 CLI 的測試預設不執行，本版本也沒有執行。
- 這項功能在 Windows 上的 provider 行程邊界行為，尚未在真實 Windows 機器上驗證。
- 角色 id 由名稱產生（例如 `u-reviewer-one`），可讀但不能自行編輯。
